# Генератор карточек товаров

Прототип AI-помощника для подготовки товарных описаний (тестовое задание «AI-разработчик»).
Сервис принимает JSON с данными о приборе и формирует черновик карточки товара для B2B-интернет-магазина:
SEO-заголовок, SEO-описание, ключевые характеристики, поисковые запросы и блок для менеджера.
Генерация идёт через Mistral AI, ключ API хранится вне кода.

Главный принцип: **модель не выдумывает характеристики**. Технические значения берутся только из входных
данных, а список недостающего формирует код, а не модель.

## Требования
- Python 3.10 или новее (разработка и проверка велись на 3.12).
- Ключ API Mistral AI (https://console.mistral.ai).
- Доступ в интернет к `api.mistral.ai`.

## Установка
Команды выполняются из корня проекта.

Windows (PowerShell):
```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy .env.example .env
```

Linux / macOS:
```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

## Настройка
Все настройки читаются из файла `.env` в корне проекта (он в `.gitignore` и в репозиторий не попадает).
Обязателен только ключ.

| Переменная | Обязательна | По умолчанию | Назначение |
|---|---|---|---|
| `MISTRAL_API_KEY` | да | — | ключ API Mistral |
| `MISTRAL_MODEL` | нет | `mistral-large-4` | модель для генерации |
| `REQUEST_TIMEOUT` | нет | `60` | таймаут запроса к Mistral, секунды |
| `MAX_RETRIES` | нет | `2` | сколько раз повторить генерацию, если ответ нарушил правила проверки |
| `MAX_INPUT_CHARS` | нет | `50000` | максимальный размер входного JSON |
| `MISTRAL_URL` | нет | `https://api.mistral.ai/v1/chat/completions` | адрес API |

Пример `.env`:
```
MISTRAL_API_KEY=ваш_ключ
MISTRAL_MODEL=mistral-large-4
REQUEST_TIMEOUT=180
MAX_RETRIES=2
```

Рекомендуется поставить `REQUEST_TIMEOUT=180`: большая модель отвечает медленно, особенно на товарах с
длинным описанием. Если приложение запущено без ключа, оно сразу завершится с понятной ошибкой.

Доступные модели и лимиты зависят от вашего тарифа Mistral. Список моделей, которые видит ваш ключ:
```bash
curl -s https://api.mistral.ai/v1/models -H "Authorization: Bearer $MISTRAL_API_KEY"
```

## Запуск
Команды выполняются **из корня проекта**, потому что файл `.env` читается из текущей папки.

Режим разработки (перезапуск при изменении кода):
```bash
uvicorn app.main:app --reload
```

Режим для сервера (без автоперезапуска, доступ из сети):
```bash
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

После запуска:
- интерфейс: http://127.0.0.1:8000
- интерактивная документация API: http://127.0.0.1:8000/docs

Изменения в `.env` и в файле промпта (`app/prompts/card_system.md`) подхватываются только после перезапуска
сервера.

Замечания для размещения на сервере:
- приложение не шифрует трафик: HTTPS обеспечивает обратный прокси (nginx, Caddy и т. п.);
- ключ API передавайте через переменную окружения или `.env` на сервере, не коммитьте его;
- в приложении нет авторизации: не выставляйте его в открытый интернет без защиты, иначе кто угодно
  сможет тратить ваш лимит Mistral;
- состояния и базы данных нет, поэтому несколько процессов (`--workers N`) работают независимо.

## Как пользоваться
1. Откройте http://127.0.0.1:8000.
2. Вставьте JSON товара в поле, нажмите «Вставить из буфера» или выберите файл `.json`.
   Готовые примеры лежат в `examples/`.
3. Нажмите «Сформировать».
4. Если для типа товара не хватает обязательных полей, сервис покажет список и определённый тип товара.
   Можно заполнить поля и нажать «Применить и сформировать» или нажать «Сформировать как есть»:
   тогда отсутствующие характеристики в карточке будут помечены «данных нет».
5. Готовую карточку можно скопировать («Копировать JSON») или сохранить в файл («Скачать JSON»).

## Формат данных

### Вход
```json
{
  "name": "МК110-224.8Д.4Р [М01]",
  "manufacturer": "ОВЕН",
  "specs": {
    "Тип": "комбинированный модуль ввода/вывода дискретных сигналов",
    "Степень защиты корпуса": "IP20"
  },
  "description": "Описание или фрагмент технического паспорта",
  "url": "https://www.souz-pribor.ru/product/mk110-8d-4r/"
}
```
Все поля необязательны на уровне формата, но для генерации нужно как минимум название товара.
Пустые значения (`""`, `null`, пробелы) считаются отсутствующими.

### Выход (`POST /api/generate`)
Запрос: `{"raw": "<JSON товара строкой>", "extra": {...}, "force": false}`, где `extra` — дополнительные
данные от пользователя, а `force` разрешает генерацию при недостающих полях.

Ответ:
```json
{
  "status": "ok",
  "product_class": "токовые клещи",
  "missing_fields": [],
  "product": { "...": "данные товара после объединения с extra" },
  "card": {
    "seo_title": "...",
    "seo_description": "...",
    "key_specs": [{ "name": "...", "value": "..." }],
    "search_queries": ["...", "...", "..."],
    "manager_block": "...",
    "missing_info": []
  },
  "warnings": []
}
```
`status` равен `ok` или `needs_more_data` (тогда `card` пустой, а `missing_fields` содержит список полей).

Коды ошибок: `400` — некорректный JSON, `413` — слишком большой вход, `422` — некорректные данные
товара, `502` — ошибка или таймаут при обращении к Mistral.

## Как это работает
1. **Разбор и проверка входа.** Некорректный JSON и неверные типы дают понятную ошибку.
2. **Определение класса товара** по ключевым словам в названии и поле «Тип». Сейчас описано два класса
   (модуль ввода/вывода дискретных сигналов, токовые клещи) и общий запасной класс. У каждого класса свой
   список обязательных полей, включая характеристики внутри `specs` (см. `app/services/product_classes.py`).
3. **Проверка полноты по классу.** Список недостающих полей формирует код. Значение `-` в характеристике
   считается заполненным: это значение с сайта («не применимо»), а не пропуск.
4. **Запрос к Mistral** в режиме JSON, температура 0,2. Системный промпт — `app/prompts/card_system.md`.
5. **Проверка ответа** (`app/services/validator.py`): заголовок до 70 символов, описание 800–1200
   символов, 3–5 поисковых запросов и главное — каждое число в тексте должно присутствовать во входных
   данных. При нарушениях модели возвращают список ошибок и просят исправить, до `MAX_RETRIES` раз.
   Если во входных данных менее трёх характеристик, нижняя граница длины описания считается мягкой
   (предупреждение в `warnings`), чтобы не провоцировать модель на выдумывание фактов.
6. **Недостающие данные добавляет код.** Всё, что модель написала про «пробелы», удаляется;
   в `key_specs` добавляются строки «данных нет» по недостающим характеристикам класса, а `missing_info`
   заполняется из списка недостающих полей.

## Структура проекта
```
app/
  main.py                    приложение FastAPI, раздача интерфейса
  config.py                  настройки из .env
  schemas.py                 модели данных (вход, карточка, ответ API)
  api/routes.py              эндпоинт POST /api/generate
  services/
    product_classes.py       классы товаров и обязательные поля
    completeness.py          проверка полноты, объединение данных, список недостающего
    generator.py             вызов Mistral, повторы при нарушениях
    validator.py             проверки ответа модели
  prompts/card_system.md     системный промпт
  static/index.html          интерфейс
examples/                    примеры входных данных (два товара)
requirements.txt             зависимости
.env.example                 шаблон настроек
```

## Возможные проблемы
| Симптом | Вероятная причина и решение |
|---|---|
| Приложение не стартует, ошибка про `mistral_api_key` | не найден `.env` или в нём нет ключа. Запускайте из корня проекта |
| `Mistral вернул ошибку 401` | неверный или удалённый ключ |
| `Mistral вернул ошибку 429` | превышен лимит запросов. На некоторых тарифах для части моделей лимит нулевой: смените `MISTRAL_MODEL` на доступную вам модель и перезапустите сервер |
| `Mistral не ответил за отведённое время` | увеличьте `REQUEST_TIMEOUT` (например, до 180) или сократите описание в данных |
| `Не удалось связаться с Mistral` | нет доступа к `api.mistral.ai` (сеть, VPN, прокси) |
| `ModuleNotFoundError: No module named 'app'` | команда запущена не из корня проекта |
| Изменения в `.env` не применяются | перезапустите сервер: настройки читаются один раз при старте |

## Ограничения
- Классов товаров два (плюс запасной), новые категории нужно описывать вручную в `product_classes.py`.
- Класс определяется по ключевым словам, а проверка полноты — по точному названию характеристики
  (регистр, пробелы и знаки препинания не важны).
- Проверка выдумок охватывает числа; нечисловые значения (названия интерфейсов, протоколов) она не ловит.
- Автоматическое получение характеристик со страницы товара по `url` не реализовано, недостающие данные
  вводятся вручную.
- Повторы при лимитах Mistral (ошибка 429) не реализованы: такой запрос завершается ошибкой 502.
- Для строк характеристик с несколькими вариантами исполнения значение сохраняется как есть, выбор варианта
  остаётся за пользователем.
- Нет авторизации, хранения результатов и автотестов.
